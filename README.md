# m's games and stuff

a tiny arcade. black glass, lowercase, comic sans. games open in-page and you
refresh to get back to the hub.

## adding a game

1. drop the game's `.html` into `games/`
2. drop its picture in next to it with the same name — `games/snake.html` wants
   `games/snake.png` (`.jpg` `.jpeg` `.webp` `.gif` `.avif` `.svg` also work)
3. that's it. the card makes itself, and the list stays alphabetical

the display name comes from the filename: `geometry-dash` shows up as
"geometry dash". a file starting with `_` is ignored, which is handy for templates.

no picture? the card is just its title, no empty box.

## running it locally

```
start.bat          (or: python serve.py)
```

then open <http://127.0.0.1:8123>. the server rescans `games/` on every request,
so a dropped-in game appears on refresh. `python serve.py --open` pops the browser
open for you.

<http://127.0.0.1:8123/svg/index.svg> is the same page through the jsDelivr entry
point, which is how it behaves once hosted. test that one before you push.

## hosting it

the page reads `games.json`, so a host needs no server at all — just the files.
that manifest is generated by:

```
python build_games.py
```

**GitHub Pages** (recommended — free, renders html, `githubname` url):

```
git init && git add -A && git commit -m "m's games and stuff"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

then repo → settings → pages → source: `main` / `/ (root)`.
your site is at `https://<you>.github.io/<repo>/`.

`.github/workflows/update-games.yml` reruns `build_games.py` on every push that
touches `games/`, so dropping in a game and pushing is all you ever do.

## jsDelivr

jsDelivr will not serve your `.html` *as* html. it sends `Content-Type: text/plain`
with `X-Content-Type-Options: nosniff`, so opening `.../index.html` prints the
source instead of running it. verified:

```
$ curl -sI https://cdn.jsdelivr.net/gh/<user>/<repo>@main/index.html | grep -i content-type
Content-Type: text/plain; charset=utf-8

$ curl -sI https://cdn.jsdelivr.net/gh/<user>/<repo>@main/svg/index.svg | grep -i content-type
Content-Type: image/svg+xml
```

but it *does* hand the html over as data — `Access-Control-Allow-Origin: *` — and
`.svg` is served as a real type whose scripts run when you open it directly. so
`svg/index.svg` is the entry point: it fetches `index.html`, points the relative
paths back at the repo root, and renders the page in place.

**the site on jsDelivr:**

```
https://cdn.jsdelivr.net/gh/tsindev/ms-games-and-stuff@main/svg/index.svg
```

the address bar stays on that `.svg` url. `index.html` also works normally on
GitHub Pages, where html is served as html in the first place — so you can have
both, and neither needs the server.

notes:

- jsDelivr caches `@main` for up to 7 days. after a push, purge it:
  `https://purge.jsdelivr.net/gh/tsindev/ms-games-and-stuff@main/svg/index.svg`
- the svg route needs javascript, since the page is handed to it by javascript.
- a game that ships its own `<base>` (pulling assets from a cdn) keeps it; the rest
  get one pointing at their own folder, so `games/snake.png` still resolves.

## files

| file | what it does |
| --- | --- |
| `index.html` | the hub — reads `games.json`, builds the cards, hosts the game iframe |
| `style.css` | black liquid glass |
| `games/` | the games and their pictures |
| `build_games.py` | scans `games/` → `games.json` |
| `svg/index.svg` | the jsDelivr entry point (see above) |
| `serve.py` | local server, rescans on every request |
| `start.bat` | double-click launcher for `serve.py` |
